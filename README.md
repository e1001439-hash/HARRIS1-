# Harris LINE 髮廊助理

用 LINE 官方帳號接待客人、整理需求與通知店主的小型程式。店主可接手對話，再自行恢復自動回覆。資料保存在 PostgreSQL，程式重啟後仍保留待辦與接手狀態。

收到訊息後先保存原文通知，由獨立迴圈推播給店主，不等待 AI 或客人回覆。AI 完成後補上同一待辦的「需求整理更新」；兩階段各自去重。較新訊息會抑制過期整理，但不抹除原始通知，因此可能收到「初步通知」及「整理更新」各一則，會分別使用 LINE 訊息額度。人工接手後仍可整理客人補充／更改的時段與項目，但不自動回客人，也不覆寫店主的接手或恢復決定。

本輪以已發佈的 `401bf62` 為基準，只在本地改善有界上下文對話，未推送或部署，沒有真API／LINE呼叫。既有四題真實店主AI預覽曾成功，但不代表本輪自然生成品質；客人後續更改需求的通知仍待真實驗收。線上仍沿用本人核准的`live/ai`設定，本輪未操作Render或查正式資料庫。證據與限制見 [驗證紀錄](docs/VALIDATION.md)。

預約入口使用本人確認的 [Harris 預約](https://harrishair.tw)，沒有接入預約平台，也無法查空檔、建立訂單或驗證預約。客人想預約、客人說已預約、店主確認，會分開記錄。未提供的價格、地址與營業時間不能讓 AI 補猜。

AI依本客人有界歷史接話，程式先整理項目、髮長、客群與本則需求；金額從 [已核准資料](knowledge/facts.json) 查表，模型只以placeholder引用事實，組合已審閱口語銜接與順序。合格草稿保留實際措辭，不再全部換成固定長模板；不合格則用本則安全簡答。來源是本任務主對話已核圖後轉錄，詳見 [價表來源](knowledge/price-source.md)，不重新折扣。剪髮700元、一般11:00–18:00維持；特定日營業、休假、地址、未知價格／政策仍由Harris確認。未新增圖片辨識或發圖。

身份是「Harris 的訊息小幫手」；首次對客人嘗試送出自動回覆時明說是 AI，狀態隨資料庫保存，重啟與歷史清除不重新介紹。每則客人回覆最多一個 emoji。預約依然僅收集需求交 Harris 確認，不查空檔或成立訂單。既有人工接手狀態不會因新版部署而解除。固定模式仍只回覆收訊確認後轉人工，不會使用這些 FAQ。完整操作見 [設定與上線指南](docs/SETUP.md)。

「胸上染髮多少→我是新客」可承接L與新客價格，只問缺項，不每次貼價表／預約網址或追問預約；謝謝可自然收尾。一旦明確預約需求仍立即轉人工：首則「週六兩點」回待Harris確認，其後「三點也可以」只整理通知Harris，不自動回客人。上下文按客人與來源時間隔離、限最近10 turns／30天；不會成為永久偏好。這是有界對話，不保證任意自由聊天；實際mock範例見 [對話驗證](docs/CONVERSATION_EXAMPLES.md)。

店主 `/preview 剪髮多少錢？`（或 `/預覽 問題`）只在測試模式且啟用 AI 時使用，正式模式停用；保留店主身分，不需配對或找朋友。只顯示給店主、不讀取他人歷史、不建立待辦／預約、不改人工接手；每10秒一次、24小時20次，包含失敗嘗試。一般問題會使用實際模型及核准回覆規則，可能產生 API 用量；直接轉人工的規則題明示未呼叫 AI。成功預覽不代表已完成客人端到端驗收。

## 先在本機試用

需要 Node.js 24 LTS 與 npm。在專案根目錄執行：

```bash
npm ci
npm run check
npm test
npm run build
npm run demo
```

Demo 使用內嵌 PostgreSQL、假的 LINE 與 AI，不會傳送真實 LINE 訊息，也不需要金鑰。資料保存在已忽略的 `.local/demo`。保持 demo 執行，在另一個終端機執行：

```bash
npm run demo:send -- "我想預約剪髮"
```

在 `.local/demo-outbound.jsonl` 查看模擬回覆與店主通知；其中只有 demo 假資料。Demo 預設使用本機 3000 連接埠，請勿把它當正式 webhook。

## 常用指令

| 指令 | 用途 |
| --- | --- |
| `npm ci` | 按 lockfile 安裝相同版本的套件 |
| `npm run check` | TypeScript 檢查 |

`GET /healthz` 檢查程式存活，`GET /readyz` 檢查資料庫是否可用。LINE 使用 `POST /webhook`，程式會以原始請求內容驗證簽章。

## 安全加入測試者

最小啟動只需安全填入四欄：`DATABASE_URL`（資料庫連線）、`LINE_CHANNEL_SECRET`（LINE 簽章密鑰）、`LINE_CHANNEL_ACCESS_TOKEN`（LINE 發訊憑證）、`OWNER_LINE_USER_ID`（店主本人識別碼）。店主在 Harris channel 的 **Your user ID** 由本人填入 Render 安全欄位，不能填官方帳號 ID `@nsw7233k`。保留 `BOT_MODE=test`（測試模式）、`RESPONSE_MODE=fixed`（固定回覆）；`TEST_LINE_USER_IDS`（選填的手動測試名單）可省略或留空，AI 金鑰／模型也不需要。儲存庫已附 `knowledge/salon.md` 與 `knowledge/facts.json`，初次固定測試不必另行提供這兩份檔案。

以下是真實服務取得授權並完成連線後的操作，不是本輪已發訊的紀錄：

1. 店主以個人 LINE 對官方帳號傳 `/配對`，私下收到有效五分鐘、難猜的一次性文字「測試配對 <碼>」。只把這段文字私下交給指定的另一位 LINE 使用者。
2. 指定的人把該文字傳給官方帳號。此時只留下待確認候選，不自動授權、不回覆該人，也不呼叫 AI；配對碼與候選原文不進一般事件。
3. 店主傳 `/配對狀態`，查看 P 代號與到達時間，向指定的人核對，再傳 `/確認配對 P000001`。確認後，對方的**下一則一般訊息**才進固定接待與店主通知。
4. `/取消配對` 關閉未確認窗口；`/移除測試 P000001` 撤銷動態配對授權。若同一人也在手動靜態名單，仍需從安全環境設定另行移除。店主不能同時當測試客人。

配對只在測試模式開放。授權在重啟後保留至移除，更換 channel secret 或店主 ID 會隔離舊授權。撤銷會阻止後續或尚未發出的接待，已開始的 AI 請求或外送無法撤回。不要把配對碼、token 或含憑證的連線網址貼到聊天或日誌。完整期限與清理規則見 [SETUP.md](docs/SETUP.md)。

## 店主如何使用

店主需先加官方帳號好友，並把自己的 LINE user ID 安全設定為 `OWNER_LINE_USER_ID`。在自己的個人 LINE 對官方帳號傳送：

| 指令 | 操作 |
| --- | --- |
| `/help` | 查看指令 |
| `/pending` | 查看待辦 |
| `/pending T000001` | 依上一頁提供的代號，查看較舊待辦 |
| `/take C000001` | 接手指定客人，暫停其自動回覆 |
| `/resume C000001` | 恢復指定客人的自動回覆 |
| `/done T000001` | 結束待辦 |
| `/confirm T000001` | 由店主人工確認該待辦的預約 |
| `/feedback T000001 正確回法或問題說明` | 記錄需要改善的回覆 |

請用實際通知中的客人／待辦代號。從 LINE 官方帳號後台手動回覆前，先使用 `/take`；程式不保證偵測後台手動發訊。`/confirm` 只記錄店主的確認，沒有查詢預約平台。回饋存在私人資料庫，經整理、去識別化與審閱後，才更新 [店務指南](knowledge/salon.md)。

## 上線前準備

先閱讀 [SETUP.md](docs/SETUP.md)，依授權順序核對費率、關閉自動部署、推送新本地 commit，再設定四個安全欄位、資料庫 TLS、Web Service 與 LINE webhook，之後由店主確認測試者。預設為 `BOT_MODE=test`、`RESPONSE_MODE=fixed`；固定回覆測試通過且店務知識經確認後，再設定 AI，最後才切換正式服務。

憑證只放本機未追蹤的 `.env` 或部署平台的安全環境設定，請勿貼到聊天或 Git。客人訊息、資料庫備份與未去識別化回饋也不得加入 Git。Render、LINE 及 OpenAI 的費用各自計算，方案與額度以上線時的官方資訊為準。
